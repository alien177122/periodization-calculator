# Руководство: переписывание текстов по стандарту ASD S1 (строгий режим)

**Дата:** 2026-10-25 · **Репо:** Web_Calculator · **Ветка:** refactor/bundle-optimization · **План работ:** docs/content-rewrite-plan-2026-10-25.md

**Назначение:** по этому файлу редактор или агент берёт любую главу или любой экран и переписывает без дополнительных вопросов — с сохранением структуры, чисел, терминов и смысла.

---

## 0. Как пользоваться

### 0.1 Кто исполнитель

Редактор или агент, умеющий читать TS-литералы (тексты лежат в коде как строки) и запускать `node`, `npm test`, `npm run typecheck`.

### 0.2 Маршруты чтения

| Твоя задача | Прочитай в этом порядке |
|---|---|
| Переписать главу теории | §6 стандарт → §10 плейбук главы → §11 шаблоны → §12 валидатор → §13 приёмка |
| Переписать экран / состояния | §6.4 UI-правила → §9 плейбук поверхности → §11 шаблоны → §13 приёмка |
| Проверить готовую волну | §13 QA и DoD |
| Спорный термин или токен | §7 глоссарий → таблица предохранителей §2.2 |

### 0.3 Пять правил работы

1. **Тесты главнее правки.** Правка валит тест — сначала проверь, не нарушил ли ты инвариант (§6.5). Ослаблять assert запрещено.
2. **Числа — один в один.** Единицы, диапазоны, пороги. На каждую переписанную тему ведётся claim ledger (§11.3).
3. **Сначала слияние, потом деление.** Корпус рубленый (§2.1): главный приём — собрать фрагменты короче 8 слов в предложения 8–20, а не резать длинные.
4. **Порядок правил при конфликте 1→7 (§6.0):** факты → структура → смысл → терминология → длина → стиль → типографика.
5. **Валидатор + ручное ревью — оба.** Валидатор не проверяет смысл и императивы (§12.2).

### 0.4 Что считается пользовательским текстом

Всё, что читает пользователь: лекции и определения теории, карточки, заголовки секций, подписи графиков, кнопки, placeholder, aria-label, состояния loading/empty/error/offline, тосты, PWA-описания, юридические строки, серверные письма.

Не пользовательский текст: `id` и технические ключи, CSS-имена, комментарии (`theory.ts:2510` — единственная «1RM», в комментарии), значения `pattern` — это схемы (`@`, `~` там законны), числа-константы из расчётной логики.

### 0.5 Легенда статусов задач

✅ сделано · 🔄 в работе · ⬜ не начато · ⏸ приостановлено (стоп-сигнал из §15).

### 7 метрик приёмки любой волны

1. Проза ≤20 слов — 100%.
2. Полоса 8–20 в прозе — ≥90% (baseline: 56%).
3. Фрагментов короче 4 слов в прозе — 0 (baseline: 8,2%).
4. Инструкций с двумя императивами — 0 (ручное ревью).
5. Запрещённых синонимов вне глав-хозяев — 0 (валидатор).
6. Инварианты (id, шаги, маркеры 28/4/3, числа) — 100%.
7. `npm test` зелёный (число фиксируем прогоном; baseline 275), typecheck чисто, валидатор 0 в зоне волны.

## 4. Читатель и учебная модель

### 4.1 Три портрета

| Портрет | Что знает до входа | Основная трудность |
|---|---|---|
| Новичок первого цикла | проценты, RPE, «1ПМ» — тёмный лес | не понимает, где взять тест и куда записать; боится «отказа» |
| Вернувшийся атлет | устаревший словарь: сеты, повторение | путает отдых (внутри тренинга) и восстановление (между) |
| Цифровой максимизатор | знает %1ПМ, RPE, e1RM | хочет формулу-гарантию; игнорирует оговорки и мед-классы |

### 4.2 Слои узнавания

1. узнай (карточка) → 2. пойми (lecture) → 3. примени (расчёт/журнал) → 4. проверь (check-in, метрики).

### 4.3 Схема главы

задача → определение → механизм → пример → применение → ошибка → проверка. Одна идея на абзац; термин вводится до использования; один сквозной пример из существующих данных; связи через chapterLink, без хардкода «01 ·».

## 6. Стандарт ASD S1 (строгий)

### 6.0 Приоритет правил при конфликте (сверху вниз)

1. Факты и числа → 2. структурные инварианты → 3. смысл и оговорки → 4. терминология → 5. длина → 6. стиль → 7. типографика. Правило 5–7 не может нарушить 1–4. Правка валит тест — тест главнее (§0.3).

### 6.1 Длина

- Максимум 20 слов — жёстко, во всех полях прозы и bullets.
- Норма 8–20 для прозы: lecture, definition, caseStudy.body, lede, checkIn.answer.
- Нижняя граница не применяется к: bullets, pattern, callout, заголовкам, UI-строкам, callout.value.
- Одно предложение — одна точка. «И», «а», «что» не начинают новый тезис.
- Три предложения подряд короче 6 слов — дефект (лозунги).
- Счёт слова: токен букв/цифр = 1 (1ПМ, 6,7%, mTORC1, e1RM, 4,5–6,5); дефис не делит; число+единица через пробел = 2 (0,1 кг); в формуле каждое значение отдельно; пунктуация, тире, кавычки, скобки не считаются; сокращение = 1.

### 6.2 Один каноничный термин

- Канон: 1ПМ, подход, повторение, упражнение, вес, нагрузка, восстановление, сон, глюкоза, инсулин, гликоген, клетка, MPS, MPB.
- Развод: вес (кг) / интенсивность (%1ПМ) / нагрузка (объём работы); отдых (между подходами) / восстановление (между тренировками); подход / серия — только подход.
- Эпоним: «формула Эпли» — имя; первое употребление с привязкой: «формула Эпли для расчёта 1ПМ».
- Аббревиатуры (mTOR, mTORC1, AMPK, GLUT4, HOMA-IR, MPS, MPB, RPE, RIR, e1RM): полная форма при первом употреблении, дальше коротко.
- Запрещены улучшатели: «иначе говоря», «проще сказать», «по сути».
- Запрещённые синонимы (§2.2, вне глав-хозяев): 1RM, %1RM, сет, серия, повтор, раз, движение, масса, отяжеление, рекуперация, «рост белка».

### 6.3 Одна инструкция — одно действие

Императив в строке-указании — ровно один. «Сделай X и проверь Y» — два, разделить. «Сделай X, чтобы получить Y» — один. «Если A, сделай B» — один. Команды в caseStudy дробятся как bullets. Валидатор императивы не ловит надёжно — ручное ревью.

### 6.4 UI и доступность

- Инвентаризация всех строк экрана: кнопки, подписи, placeholder, aria-label, состояния loading/empty/error/success/offline, тосты.
- Ошибка = что случилось + почему + что делать.
- Кнопка = глагол + объект («Сохранить расчёт», не «Сохранить»).
- Пустое состояние = констатация + действие.
- Загрузка = глагол настоящего + объект.
- 393px: нет горизонтального скролла; touch ≥44px; hero ≤40 символов.

### 6.5 Защищённые инварианты

- lecture 3–6 абзацев (в 02 — не меньше 3), bullets ≤3, callout ≤3, caseStudy ≤3.
- id, шаги, названия глав — как сейчас; маркеры «Якорь:» ×28, «Запомнить:» ×4, «Что запомнить:» ×3 (текст после маркера менять можно, сам маркер — нет).
- Тестовые числа — точно; `4,5–6,5` в том числе в callout.value; каркас 01/02, `.ta-frac`, виджеты — не трогать.
- Комментарий theory.ts:2510 — единственная «1RM» в репо.

### 6.6 Без потерь

- Новые факты не добавлять; содержание не удалять — делить, сливать, переносить, объединять с причиной.
- Числа, единицы, диапазоны — точно.
- Claim ledger обязателен; статусы только «перенесён»/«объединён».
- Упрощение не отменяет оговорок, условий, максимумов.

### 6.7 Типографика

- Десятичная запятая: 1,3; 0,1 кг. Диапазон — тире: 4,5–6,5%.
- Меньше/больше словами: «ниже 4,5%», «выше 70%»; «около 9%», не ~9%.
- Слэш с пробелами: 1,3 / 1,2 / 1,1.
- Русские кавычки; многоточие одним символом; неразрывный пробел перед единицами.
- Исключение: pattern (схемы) — `~`, `@` законны.

### 6.8 Восемь примеров «было → стало» на живых цитатах

**№1 — канцелярит + числа (theory.ts:1099, глава 01)**
- Было: «В приложении используется модифицированная формула Эпли с консервативными коэффициентами (1.3/1.2/1.1). При малых повторах (< 5) точность ниже. Идеальный диапазон для теста — 5–8 повторений до отказа. Результат округляется до 0.1 кг.»
- Стало: «В приложении работает формула Эпли для расчёта 1ПМ с консервативными коэффициентами 1,3 / 1,2 / 1,1. Точность ниже, если тест сделан меньше 5 повторений. Лучший тест — 5–8 повторений до отказа. Результат округляется до 0,1 кг.»

**№2 — три идеи в одном предложении (theory.ts:1151, карточка 01)**
- Было: «Сухожилия адаптируются при деформации 4,5–6,5%, что соответствует тяжёлым нагрузкам (>70% 1ПМ, рабочий ориентир 85–90% при контроле техники).»
- Стало: «Сухожилия адаптируются при деформации 4,5–6,5%. Такая деформация совпадает с нагрузкой выше 70% 1ПМ. Рабочий ориентир — 85–90% при контроле техники.»

**№3 — слияние фрагментов (theory.ts:1941, глава 06)**
- Было: «Ниже примерно 4,5% стимула для ремоделирования мало. Полоса 4,5–6,5% — рабочее окно. Около 9% и выше — зона травматизма, не „ещё жёстче“.»

## 8. Доказательность и безопасность

- Классы утверждений: факт, механизм, наблюдение, гипотеза, рекомендация. В прозе давать маркер класса словами: «связано», «наблюдается», «работает», «предполагается», «делай».
- Не обещать: «вылечить», «обратить», «гарантировать».
- Наблюдение не равно причине: «высокий объём связан с…», не «объём вызывает…»; механизм в отдельном предложении, если он есть.
- Красные флаги (боль в сухожилии, потеря веса, сбой пульса): спокойно, одно действие — «останови нагрузку и обратись к врачу».
- Мед-ревью обязательно: 07 кардио, статьи «Привычки и диабет», «Еда на ночь», «Анаболики и сосуды», фармакологический блок в 02 mtor.
- Утверждение без источника не усиливать расчётом и категоричностью.

## 12. Валидатор

**Команда:** `node scripts/content-s1-validate.mjs [--chapter <id>] [--files a.ts,b.ts]` — код возврата 0, только если в выбранной зоне нарушений нет.

### 12.1 Что проверяет

1. Длина ≤20 слов по алгоритму §6.1 (prose-поля, bullets); «три подряд короче 6» в lecture.
2. Полоса 8–20 — информационная метрика (не нарушение).
3. Запрещённые синонимы по правилу — с allowlist глав (§2.2); спорные токены («раз», «движение») — по границе слова.
4. Счёт маркеров: «Якорь:» 28, «Запомнить:» 4, «Что запомнить:» 3 (глобально).
5. Реестр защищённых чисел: существование в корректных местах; чужие главам токены — нарушение.
6. Типографика в прозе: десятичная точка, `~`/`@` вне pattern, угловые `<`, `>` при числе, прямые латинские кавычки, двойной дефис в диапазоне; pattern-исключение.
7. hero-tips.ts: длина ≤40 символов, запрещённые синонимы.

### 12.2 Чего не проверяет (ручное ревью)

Смысл и логику; классы утверждений (§8); двойные императивы (§6.3); a11y-качество выше строки; UI-строки вне data-файлов (инвентаризация B-этапа); строки, вычисляемые в TS.

### 12.3 Allowlist

В строке источника допустимо ` // s1-allow: rule1,rule2` — валидатор пропускает эти правила для строки. Ставить только обоснованно: pattern, схема, техническая метка.

### 12.4 Формат вывода

```
FILE line:col  RULE  snippet
...
summary: files=N strings=M prose=J violations=V (по правилам: length=…, canon=…, typo=…, markers=…, registry=…, hero=…)
```

### 12.5 Почему не в npm test

Тесты — контракт продукта; валидатор — производственный инструмент, вызывается по волне. Отдельная команда — не шаг CI. Число тестов не хардкодим — фиксируем фактический прогон.

### 12.6 Baseline-прогон (25.10)

Результаты — в план (docs/content-rewrite-plan-2026-10-25.md §1). После каждой волны — второй прогон той же зоны, в отчёт идёт пара «до → 0».
