### 1.3. Лекционная модель уже существует

`packages/shared/src/data/theory.ts`:

- `LectureLessonGroup`: `step`, `title`, `lede`, `topics[]`, `checkIn` (вопрос/ответ).
- `LectureTopic`: `lecture[]` (абзацы), `definition`, `pattern`, `bullets`, `callout`, `caseStudy`, `chapterLink`.

То есть «лекции» частично внедрены: это не greenfield. Нет трёх вещей:

1. **Маршрута ученика.** В Теории главы равноправны; маршрут «от простого к сложному» есть только в самоучителе (`learning-path.md`), который из приложения недоступен.
2. **Прогресса обучения.** `checkIn` — статичный вопрос/ответ; отметок «прочитано / отвечено / повторить» нет, состояние не хранится.
3. **Связи лекция → действие.** Из активной тренировки нет перехода к нужной теме (RPE, кластер, тест-неделя), хотя `chapterLink` в данных уже умеет связывать темы между собой.

## 3. Переделка текста по avoid-ai-writing

### 3.1. Что берём из гайда, что адаптируем

Гайд и его детектор откалиброваны под английский: `npx avoid-ai-writing-detector` на русском корпусе использовать как гейт нельзя. Переносим категории:

| Категория гайда | Правило для корпуса |
|---|---|
| Language: filler, copula avoidance, template phrases | Убрать «важно / главное / ключевой / стоит отметить», «позволяет» → прямой глагол, «не только» без второй части смысла |
| Structure: «It's not X, it's Y» | «не X, а Y» оставлять только при реальном противопоставлении; декоративные — переписать утверждением |
| Structure: formatting (em dash) | Русская типографика тире допускает. Цель не «0 тире», а конец тире как универсального союза: замена на двоеточие, точку или «поэтому». Не трогать диапазоны (4,5–6,5%), схемы (2+2+2), `pattern`-строки и чипы |
| Structure: rhetorical question openers | Тема начинается с утверждения. Вопросы в `checkIn` — функциональные, остаются |
| Content: significance inflation, superficial -ing analyses | Убрать оценки («это меняет подход к…»), оставить механизм и числа |
| Communication: generic conclusions | Финал группы — конкретное действие или «что запомнить», не «так вы достигнете…» |
| Meta: rhythm and uniformity, over-polishing | В каждой теме ≥1 короткое предложение (≤7 слов) при сохранении потолка 20; абзацы 2–5 по плотности идеи, а не одинаковые |
| Метафоры | ≤1 на `lede` (действующее правило); повторяющиеся штампы («прораб», «магия») — одна на главу, дальше механизм своими словами |

Жёсткие ограничения, которые не пересматриваются:

- Числа, схемы, источники, URL, id — 1-в-1. Ничего не «уточнять» без источника.
- Тестовые инварианты глав: `lecture.length` ∈ [3..6], `caseStudy ≤ 3`, `callout ≤ 3`, бан-слова глав (`прораб` у progression и т.п. — читать тест главы перед правкой).
- Чипы/`pattern`/VOLUME_METHOD — конвенция, не проза (решение 26.10).
- `server/schema.js` и имперсональные серверные сообщения — без правок (решение 26.10).
- Лейблы, на которые есть тестовые пины, менять только вместе с пинами.

### 3.2. Примеры (до → после)

1. `theory.ts`, lede mTOR:
   «mTORC1 — не выключатель роста, а прораб на стройке: он смотрит, что есть на площадке, и решает, начинать ли работу.»
   → «mTORC1 — прораб на стройке: без заказа, материала и сметы работа не начинается.»
   (Метафора оставлена одна, шаблон «не X, а Y» убран.)

2. `theory.ts`, лекция mTOR:
   «Мышца растёт не потому что „включилась магия после подхода“. Клетка всё время считает, хватает ли причин тратить энергию на новые белки.»
   → «Мышца растёт, когда у клетки есть повод тратить энергию на новые белки. Поводы складываются: нагрузка, аминокислоты, запас энергии.»

3. `theory.ts`, кейс про микрокластер:
   «Главное — не превращать один подход в бесконечную череду микро-подходов: сделал паузу, качественно завершил задачу и на этом закончил.»
   → «Не превращай подход в бесконечную череду микро-подходов: сделал паузу, закончил повторения, остановился.»

4. Хаб главы «Механика»:
   «Почему один и тот же вес ощущается по-разному: рычаги и позиция.»
   → «Один и тот же вес ощущается по-разному: меняются рычаги и позиция.»
   (Не риторика, но частый шаблон «почему» в анонсе; проверять по месту.)

### 3.3. Процесс

1. **Инвентарь (S).** `scripts/quality/copy-lint.mjs`: русский детектор по §3.1, отчёт по файлам/полям с разделением «проза» vs «чипы/схемы/тест-пины». Снапшот «до» в `docs/`.
2. **Пилот (S).** Одна глава целиком (предложение: mtor — самый плотный набор штампов) + `hero-tips.ts`. Ревью до/после человеком.
3. **Волны (M).** Дальше по главам, как в S1: basics → progression → mechanics → strength → tendons → specs → tiers/top3 → cardio → статьи для чтения → selfstudy A–O → UI-строки по списку B3.
4. **Гейты после каждой волны.** `npm test`, `npm run typecheck`, `npm run lint`, валидатор корпуса S1 (0 нарушений), copy-lint (дельта к снапшоту), DOM-прогон 393px на затронутых экранах.
5. **Метрики приёмки.** «важно/главное/ключевой» в прозе лекций → 0; «не только» → 0; «не X, а Y» — только осмысленные, список оставшихся в отчёте; тире в prose-полях ≤ ~1,5/1000 зн.; 0 риторических открытий тем; у каждой лекционной темы разброс длины предложений (есть ≤7 слов и ≥12 слов).

### 3.4. Что не делаем

- Не гонимся за «0 тире» и не ломаем русскую пунктуацию.
- Не применяем англоязычный детектор как автоматический вердикт по русскому тексту.
- Не переписываем всё подряд: чипы, схемы, тест-пины, серверные техсообщения остаются.
- Не коммитим без команды.
