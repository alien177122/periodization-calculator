## 2. Поток S1 · Свободный состав дня и схемы (M) — ✅ слой данных и редактор схем 2026-11-13

**Что.** В конструкторе день собирается из 2–8 упражнений: 4 основных + 0–2 дополнительных как рекомендуемый шаблон, не ограничение. У каждого упражнения в дне своя схема подходов.

**Сделано.**

- `CustomSplit.schemeOverridesByDay?: Partial<Record<SplitDayNumber, Record<string, WeekScheme>>>` — перекрытие схемы упражнения в конкретном дне. Пустое поле = поведение как сейчас (старые сплиты миграцией не трогаются).
- `packages/shared/src/data/split-schemes.ts`: `resolveDayScheme` (перекрытие важнее `weekSchemes`), `withDayScheme` / `withoutDayScheme` (иммутабельно), `normalizeDayScheme` (сет 1–12, повторы 1–30), `normalizeDaySchemeOverrides`.
- `buildDayPreview` считает подходы/повторы/тоннаж по перекрытию: `5×4` вместо `4×4` меняет и число подходов, и объём.
- Синх: клиент `normalizeLoadedUser` и сервер `normalizeSchemeOverridesByDay` — битые записи отбрасываются, валидные переживают round-trip.
- `packages/shared/src/data/split-presets.ts`: пресеты **«Стандартный»** (read-only шаблон: 12 упражнений на 2 дня) и **«Короткий 4+2»** (пример владельца: 4 основных + 2 дополнительных). Шаблон неизменяем; сплит, созданный из него, — обычная копия, её можно править (и клонировать через «Повторить»).
- Конструктор: выбор пресета в диалоге создания сплита; в карточке упражнения — степперы «подходы × повторы» (тап-зоны 44px) и «как в программе» для сброса. Лимит упражнений в дне поднят с 4 до 6.
- Тесты: `tests/split-schemes.test.ts` (перекрытие, сброс, валидация, пресеты, влияние на превью, round-trip) + серверный тест PUT/GET. Гейты: typecheck ✓, lint ✓, 321/321 ✓, build ✓.

**Осталось на S1 (не блокирует S2).**

- Тоннаж недели и прогноз уже считаются по перекрытию (`buildDayPreview` → `row.scheme.sets × reps`), поэтому 5×4 меняет и тоннаж. `VolumeDonut` в «Калькуляторе» считает объём по каталогу целиком и к сплиту не относится — он не пересчитывается.
- Мягкие подсказки по объёму дня («мало для ног», «много на день») — не сделаны.
- Пометка «из пресета» в списке сплитов: добавлено поле `sourcePresetId` в `CustomSplit`, заполняется при создании из пресета, бейдж в `SplitPicker`. Кнопка «Сделать своим» пока не вынесена отдельно — копия создаётся через диалог «Создать сплит» из пресета.


## 3. Поток S2 · Объединение «Сплит» и «Тренировка» (L) — ✅ выполнено 2026-11-14

- «Стандартный сплит» = пресет текущей программы: открыл → посмотрел дни и веса → «Начать тренировку». Редактирование необязательно.

- Режимы экрана: `Программа` (выполнение + прогресс) и `Конструктор` (редактирование). Для стандартного пресета по умолчанию открывается `Программа`.

**Данные и миграция.**

- `activeProgram`, `trainingProgress(ByProgram)` читаются как раньше; новый вид — `splitId` активной программы. Миграция: если активна программа v3, создаётся ссылка на пресет «Стандартный», прогресс `completedSessions` сохраняется.
- Снимки `SplitCalculation` остаются источником весов; редактирование программы посреди цикла не переписывает начатую волну (снапшот на старте).

**Навигация.** TabNav 5 → 4. Редиректы старых ссылок: `?tab=training` → `?tab=split&view=program`. Заголовки/hero вкладки обновляются.

**Тесты.** Юнит миграции (v3 → пресет, прогресс не теряется), e2e «стандартный сплит → день 2 → завершить → 8/16», DOM 393px, старые deep links открываются.

**Риски.** Самый рискованный поток: две книги прогресса (trainingProgress vs completedDays) надо сшить без потерь; привычный вход «Тренировка» исчезает — нужен редирект и понятное имя; paywall/лимиты калькулятора не затрагиваются.

## 4. Поток S3 · Связки двух упражнений (M–L) — ✅ выполнено 2026-11-14

**Что.** Любые два упражнения дня можно связать: подходы чередуются, отдых идёт параллельно работе над вторым упражнением.

**Данные.**

```ts
export interface ExercisePair {
  id: string;
  a: string; // exerciseKey из дня
  b: string;
  restAfterA: number; // сек, дефолт 180 для базовых
  restAfterB: number; // сек, дефолт 120–180
}
// CustomSplit
pairsByDay?: Partial<Record<SplitDayNumber, ExercisePair[]>>;
```

- Журнал **не меняется**: подходы пишутся по `exerciseKey`, как раньше; e1RM и тренды считаются без изменений. Парность — метаданные плана, не новая сущность подхода.
- Схемы независимые: A 5×4, B 4×8. Когда подходы одного упражнения закончились, второе идёт соло с обычным отдыхом.

**Выполнение.** Очередь: A₁ → отдых restAfterA → B₁ → отдых restAfterB → A₂ → … Индикатор «следующее: брусья · 02:30», кнопки «пропустить отдых», «разорвать связь» (на сессию), «сделал как в плане». Фактический отдых для A = restAfterA + подход B + restAfterB — показать один раз в подсказке связки («между подходами становой ~6–7 мин»).

**Правила.** Пара строго из двух упражнений; одно упражнение — максимум в одной связке; оба должны быть в составе дня. Совпадение мышечной группы — предупреждение «конкурирующая пара», не запрет. В тест-неделю для тестируемого упражнения предлагается снять связку (тест делается свежим, без работы между подходами).

**UX конструктора.** На упражнении — «Связать» → выбор второго из дня → отдых каждого. Связка рисуется скобкой в списке дня.

**Тесты.** Построение очереди (равные и неравные числа подходов, досолонное завершение), таймеры не скачут при переключении вкладки, журнал пишет оба упражнения раздельно, e2e сценарий владельца (становая+брусья) на 393px.

**Зачем по вектору.** Меньше времени в зале при полном восстановлении → качество тяжёлых подходов и регулярность. Это прогресс к «сильнее + здоровее», не удобство ради удобства.

## 6. Открытые вопросы

> **Решены владельцем 2026-11-12 (голосовые ответы):**
>
> 1. **Калькулятор** — пока остаётся отдельной вкладкой; слияние (карточка №1) — отдельный шаг после стабилизации S2.
> 2. **Пресет** — «Стандартный» менять нельзя: read-only, выбор по умолчанию; правится только клон («Сделать своим» → копия в конструктор). Новые пресеты создаются свободно.
> 3. **Отдых и время в связке** — упрощение по решению владельца: НЕ сложный график отдыха пары, а индивидуальная интерактивная кнопка-таймер у каждого упражнения в выполнении (тапнул → таймер пошёл; сам останавливается через ~10 минут, чтобы не считал бесконечно). Атлет сам ориентируется по таймерам («3 мин после становой → брусья; 8–9 мин → следующая становая»). Счётчик подходов в выполнении НЕ ведём — «человек может забывать». Сводка времени тренировки — без отдельного UI в связке.
> 4. **Связка** — это рекомендованная группировка двух упражнений, не строгая механика: атлет может расставить как хочет, UI не должен громко предупреждать. Грамотные связки: жимовое/становое (жим ногами или присед) + тянущее; приоритет программы — ноги, мелкие группы верха в начале тренировки смысла мало (мнение владельца, в UI не навязывать). Сценарий: «рассчитать тренировку» → расчёт → «начать» → в дне два упражнения (становая, брусья) с подходами/весами и таймером у каждого.
> 5. **Старт** — L2 (выполнено 2026-11-12, см. docs/lectures-copy-plan-2026-11-10.md).
