# Креативные и смелые идеи (2026-11)

## 0. Стержень и правила игры

**Главная цель продукта — «стать сильнее и здоровее»**: сила → суставы/позвоночник/кровоток/вены → долголетие. Каждая идея ниже оценена в колонке «Сильнее+здоровее»: **прямо** (двигает по цепочке — растит силу или измеряет/защищает здоровье), **косвенно** (мотивация/дисциплина/непрерывность) или **нет** (чистое развлечение — кандидат на отсев, если не работает на удержание).

Три правила честности, заимствованные у THROUGHLINE и обязательные для «умных» фич:

1. **Не выдумывать науку.** Совет ассистента должен прослеживаться до опоры THROUGHLINE или конспекта; где данных нет — пометка «оценка автора», никаких выдуманных ссылок.
2. **Не подменять схему предсказанием.** Продукт продаёт «снимает догадки»; любая нейросеть должна снижать неопределённость, а не добавлять чёрный ящик. Прозрачные правила > нейросеть там, где правил достаточно.
3. **Ошибки советчика дороже его пользы.** Один плохой совет («подняй вес» человеку с перетреном) подрывает доверие ко всей системе. Спекулятивное помечено явно.

Фазы: **квик-вин** (недели), **средний** (1–2 месяца), **амбициозный** (квартал+).

## 1. Ассистент-авторегулятор (флагман)

- **Идея:** «сегодня ты спал 5 часов и вчера пропустил — вот скорректированная волна»: приложение пересчитывает цель недели (интенсивность/объём) по состоянию пользователя.
- **Ценность:** прямая реализация опоры №1 (бюджет ЦНС) и опоры №2 (не каждая тренировка максимальная). Сейчас волна «слепа» к жизни пользователя — пропуск и недосып ломают её молча, и пользователь либо бросает, либо перетренировывается. Ассистент делает систему живой — это главный дифференциатор против всех «калькуляторов».
- **Как (этапы):**
  - **Квик-вин (правила):** утренний чек-ин «сон/энергия/боль» (3 вопроса, 10 секунд). Детерминированные правила: сон < 6 ч или энергия ≤ 2/5 → цель недели RIR+1 и −10% веса; пропуск ≥ 2 недель → возврат на −10% с пересчётом (уже опора №2); боль в суставе → замена упражнения из каталога по мышечной группе. Всё считается в `packages/shared` чистыми функциями с тестами — без нейросети.
  - **Средний (интеграция данных):** Apple Health через Capacitor (сон, пульс покоя) — чек-ин заполняется сам; правила те же.
  - **Амбициозный (модель):** небольшая модель/LLM-слоя поверх правил, объясняющая сдвиг словами и подбирающая тон; правила остаются ограждением (guardrails), модель только формулирует.
- **Что нужно:** v1 — ничего внешнего; v2 — HealthKit-плагин; v3 — LLM API (дешёвый класс) или локальная формулировка шаблонами.
- **Фаза:** квик-вин → средний → амбициозный (пирамида, каждый этап самодостаточен).
- **Риски:** ложные коррекции (начать с 3 надёжных правил); пользователь начинает «управлять» системой ответами (врать про сон) — смягчается данными HealthKit; медицинская граница — при боли/симптомах совет «к врачу», не «потяни».
- **Сильнее+здоровее:** **прямо** (защита от перетрена = сон/ЦНС/сердце; непрерывность = сила).

## 2. Детектор плато по журналу с предложением действия

- **Идея:** если e1RM по упражнению не растёт 4+ недели при заполненном журнале — карточка «Плато в жиме» с вариантами: сменить пресет прогрессии (`progressionPresets` уже есть), сменить вспомогательное упражнение, проверить технику/сон, дождаться тест-недели.
- **Ценность:** плато — момент, когда люди бросают зал. Приложение, которое замечает плато раньше пользователя и даёт действенный шаг, удерживает именно тогда, когда удерживать труднее всего.
- **Как:** детекция — чистая функция по `buildPeakSeries`/`deltaLastWeeks` (плоскость серии при достатке данных); правила действий курированные (из конспектов); карточка в дашборде журнала, deep link в соответствующий инструмент.
- **Что нужно:** ничего внешнего; только журнал (уже есть).
- **Фаза:** средний (после дашборда 5.1).
- **Риски:** ложные срабатывания в лёгких неделях волны (детекция должна знать позицию недели в волне — иначе «плато» на делиде — ложная тревога); совет должен быть одним действием, не эссе.
- **Сильнее+здоровее:** косвенно (непрерывность) + прямо (предотвращение перегруза «дожать любой ценой»).

## 3. Предсказание 1ПМ без теста

- **Идея:** по накопленным рабочим сессиям (вес × повторения × RIR) предсказывать 1ПМ между тест-неделями: «по твоим подходам 1ПМ уже ≈ 88 — тест-неделя подтвердит».
- **Ценность:** снижает страх теста («вдруг хуже, чем было») и превращает каждую сессию в микротест. Пользователь видит силу растущей непрерывно, а не ступеньками раз в 8 недель.
- **Как:** e1RM (формула уже в `journalMetrics.e1rm`) + поправка на RIR (сеты не в отказ — e1RM занижен; поправочная таблица RPE→%1ПМ уже есть в `rpe-rir-cards`); тренд по 3–4 неделям → прогноз на тест-якорь. Чистая математика в shared, без нейросети.
- **Что нужно:** только журнал с RPE (уже собирается).
- **Фаза:** квик-вин/средний.
- **Риски:** точность — обязательно показывать как «оценка ±2 кг, тест покажет точно»; не позволять пропустить тест-неделю («оценка не заменяет тест»).
- **Сильнее+здоровее:** косвенно (мотивация) + прямой-слабый (меньше мотивационных срывов).

## 4. Анализ техники по видео (pose estimation) — спекулятивно, амбициозно

- **Идея:** пользователь снимает подход на телефон → MediaPipe Pose (on-device) выделяет скелет → приложение проверяет ключевые паттерны (глубина приседа, траектория штанги, наклон корпуса) и отмечает отклонения от предыдущих съёмок.
- **Ценность:** техника — прямой канал в «здоровье» (позвоночник/суставы). Кривая техника годами точит поясницу и плечи — это ровно та часть цепочки «сила → суставы → долголетие», которую журнал не видит.
- **Как:** MediaPipe Pose Landmarker работает в браузере (WASM/GPU) и в нативной iOS — без отправки видео на сервер (приватность + офлайн); v1 — 2–3 упражнения (присед, становая, жим), метрики: глубина (угол колена/тазобедренного), симметрия, траектория грифа; сравнение с прошлой съёмкой того же упражнения. Ленивый чанк (правило бандла), анализ на отдельном экране.
- **Что нужно:** MediaPipe Tasks Vision (~несколько МБ ленивой загрузкой), разметка эталонных диапазонов по упражнениям (ручная работа), тесты на углах.
- **Фаза:** амбициозный. **Помечено: спекулятивно** — валидация метрик против реальной техники требует калибровки на данных; до калибровки показывать только «тренд против прошлой съёмки», не абсолютные вердикты («глубина ок/не ок»).
- **Риски:** точность на камере телефона (наклон камеры рушит углы — давать гайд съёмки); ложные вердикты подрывают доверие; вес бандла (лениво!).
- **Сильнее+здоровее:** **прямо** (суставы/позвоночник).

## 5. Голосовой ввод подходов

- **Идея:** «Жим восемьдесят два с половиной на шесть» — и подход записан, руки на грифе не отпускаются.
- **Ценность:** снимает последний барьер записи (руки заняты) — работает на непрерывность журнала сильнее любой кнопки.
- **Как:** Web Speech API (Safari поддерживает на-device для ru-RU частично — проверять), для Capacitor — нативный Speech плагин; парсер — детерминированный словарь чисел/упражнений (не LLM: словарь узкий, ошибка недопустима); подтверждение карточкой перед записью.
- **Что нужно:** API распознавания (системное), парсер (pure-функция в shared — легко тестировать).
- **Фаза:** средний.
- **Риски:** шум зала; точность ru-RU в Safari; всегда показывать подтверждение — ошибка записи недопустима.
- **Сильнее+здоровее:** косвенно (непрерывность журнала).

## 6. Рынок программ из самоучителя

- **Идея:** шаблоны сплитов/пресеты прогрессии, упакованные как «программы с историей» — готовые наборы (сплит + прогрессия + кардио-дни + статьи-сопровождение), публикуемые автором (v1) и тренерами (v2, мост к вектору Б).
- **Ценность:** превращает самоучитель из контента в воронку-конвертер: статья → «применить программу из статьи» → пользователь в продукте. Для тренеров — будущий канал монетизации (см. vector-change вектор Б как отложенный).
- **Как:** формат программы — текущие `CustomSplit` + пресет прогрессии + ссылки на статьи (schema в shared); v1 — 3–5 программ автора, статичные; каталог в «Конструкторе».
- **Что нужно:** v1 — ничего (данные + UI-пикер); v2 — серверная публикация, модерация, биллинг-доля.
- **Фаза:** средний (v1) / амбициозный (v2).
- **Риски:** качество сторонних программ (v2 требует модерации — или противоречит честности THROUGHLINE); «рынок» без аудитории мёртв — сначала контент-воронка.
- **Сильнее+здоровее:** косвенно (правильные программы = правильный старт).

## 7. Недельные отчёты-наставник (детали в improvements-master 5.2; здесь — креативная надстройка)

- **Идея:** отчёт, который разговаривает голосом проводника («ты откатился на −10% после пропуска — это правильно, вот почему»), плюс **годовой отчёт**: арифметика года пользователя (сколько кг добавил, сколько недель активности, как менялось восстановление) — «твоя версия жима 80 → 120».
- **Ценность:** годовой отчёт — эмоциональный пик года удержания и главный шаринг-артефакт (виральность без соцсети). Отчёт недели — ретеншен на горизонте цикла.
- **Как:** недели — детерминированные правила (5.2); годовой — агрегация за год + шаблоны формулировок (LLM не обязателен; можно шаблонами — надёжнее).
- **Фаза:** отчёт недели — средний; годовой — средний (в декабре!).
- **Риски:** пустой год у новых пользователей — честная альтернатива «год начнётся с твоего первого цикла».
- **Сильнее+здоровее:** косвенно-сильный (мотивация на горизонте года) + прямо-слабый (health-строки в отчёте).

## 8. Геймификация циклов

- **Идея:** не «очки и значки», а **визуализация пути**: карта года из 5 циклов-волн, где каждый закрытый цикл — пройденная волна с отметкой «+7 кг»; серия недель активности («50 из 52 недель ты в системе»); тест-неделя — «вершина волны» с результатом.
- **Ценность:** геймификация опасна (шум против тишины — см. vector-change §3), но визуализация **уже существующей** арифметики (циклы, волна, год) — не шум, а карта пути: она работает на опору №4.
- **Как:** статичные компоненты по данным журнала (`chartProgress` — готовый паттерн); никаких очков/лидербордов — они запрещены стержнем.
- **Фаза:** средний (после дашборда).
- **Риски:** скатиться в «казуалку» — жёсткое правило: только визуализация фактов, нет «наград за действия».
- **Сильнее+здоровее:** косвенный (мотивация горизонта года).

## 9. Кардио-надстройки (связка с силовой волной) — детали механики в improvements-master §7, здесь креатив

- **9.1. «Интервал по ощущению»-режим** (средний): экран кардио-дня без таймера-хозяина: большая кнопка «ускорился» → «откатился» — приложение лишь считает циклы и время до восстановления, показывая тренд «восстановление становится быстрее». Прямая health-метрика без гаджетов. **Сильнее+здоровее: прямо.**
- **9.2. Пульс-восстановление как дельта** (средний): ручной ввод пульса после ускорения/восстановления; тренд за цикл. **Прямо.**
- **9.3. HealthKit-автозаполнение** (амбициозный): RestingHR, шаги, тренировки из Apple Health → health-строка дашборда. **Прямо. Спекулятивно по охвату** (только iOS-обёртка).
- **9.4. «Бюджет дня»-виджет** (квик-вин): текстовая шкала нагрузки дня по опоре №1 («сегодня тяжёлая волна RIR 2 — это уже много; кардио — лёгкое по ощущению, ок»). Правило-движок, без модели. **Прямо (защита бюджета ЦНС).**

## 10. Спекулятивные дальние идеи (сознательно за горизонтом)

- **10.1. «Цифровой двойник волны» (спекулятивно, амбициозно):** модель, которая на данных журнала многих (анонимных) пользователей уточняет индивидуальную реакцию на объём/интенсивность («тебе лучше отвечают 4 сета, чем 5»). Требует данных популяции — у нас их нет и собирать честно сложно; помечено спекулятивным и отложено.
- **10.2. Умный разбор «что если я заболею» (средний):** сценарии возврата после болезни/отпуска уже частично в опоре №2 — сделать пресеты возврата в симуляторе (2.1 improvements-master): «пропустил 2/4/12 недель» → готовый план возврата. Дёшево, полезно, не спекулятивно. **Косвенно-сильный.**
- **10.3. Аудио-проводник тренировки (амбициозный):** «сделай 5, в запасе 2, следующий — присед» голосом между подходами. Работает только после идеального текстового проводника; TTS системный. **Косвенный.**
