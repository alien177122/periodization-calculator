# TEMPLATE.md — шаблон статьи из базы знаний

Универсальный шаблон для сборки статей из структурированного корпуса (`kb-structured-*`). Демо-примеры: `A-otkaz-rir-poterya-skorosti.md`, `B-gspg-svobodnyy-testosteron.md`, `C-most-nervnaya-sistema.md`.

## 1. Принцип подачи: лестница «от простого к сложному»

Статья — самоучитель: читатель последовательно усваивает материал, и каждый уровень самодостаточен. Остановился после уровня — уже что-то понял.

Обязательная структура уровней:

- **Уровень 1 — «Просто»**: что это и зачем, без цифр и терминов сверх необходимого. Одна картинка/схема (Mermaid). Абзацы 2–4 предложения.
- **Уровень 2 — «Подробно»**: как работает, числа, таблицы. Таблица-числа + таблица «утверждение → статус → исследования».
- **Уровень 3 — «Вглубь»**: механизмы, исследования, нюансы, разногласия с наукой. Полный список исследований.

Заголовки уровней — явные: «Уровень 1 — Просто: …», «Уровень 2 — Подробно: …», «Уровень 3 — Вглубь: …».

## 2. Микроструктура текста

- Абзац = 2–4 предложения. Один тезис — один блок. Максимум 1–2 идеи на «экран».
- Короткие фразы, ясный русский (стиль переписанных глав теории).
- После каждого уровня: **«Что запомнить»** — ровно 3 буллета + опционально мини-проверка понимания (1–2 вопроса с ответом в скобках).
- Термин при первом упоминании раскрывается одной фразой; дальше — только сам термин.

## 4. Правила оформления ссылок

- В статью попадают **только URL из реестра** `study-links.jsonl` / `research-links.jsonl` (реально найденные в данных). Выдумывать, додумывать, «восстанавливать» обрезанные URL запрещено.
- **Источником считается только научное исследование** (название + URL). Видео, каналы и конспекты — не источники, а лишь происхождение материала: их упоминание допустимо только внутри текста как нейтральная отсылка («по разбору такой-то темы») и ни в коем случае не в списке источников.
- Список исследований — только исследования: `[Название](URL)`. Колонки `video_id` / «как названо в источнике» / «конспект» в список не включаются.
- Если ссылка есть в данных, но у неё нет названия — ставится рабочее описание темы (без меток описаний видео).
- Тезисы с упоминанием исследования, но без URL в данных, получают пометку: **«ссылка не найдена в данных — требует ручного поиска»** и перечисляются в `no-link-claims.md`.
- Привязка тезис→исследование — ориентировочная, по контексту упоминания; сомнительные привязки помечаются `confidence: low` в `claims-binding.jsonl`.

## 5. Правила оформления схем (Mermaid)

- 1–2 схемы на статью: одна в Уровне 1 (картина в целом), одна в Уровне 3 (протокол/граф зависимостей).
- `flowchart TD/LR`, подписи узлов на русском, `\n` внутри узлов для переноса.
- Проверка синтаксиса обязательна до публикации (валидатор).

## 6. Правила таблиц

- Таблица-числа: колонки «Показатель | Значение | Смысл | Где в данных» (происхождение материала — конспекты; в списке источников видео не фигурируют).
- Таблица утверждений: колонки «Утверждение | Статус | Исследования».
- В колонке «Исследования» — только реальные ссылки из реестра или честная пометка «ссылка не найдена в данных».

## 7. Самопроверка перед публикацией

1. Все URL статьи присутствуют в `study-links.jsonl` (валидатор).
2. Все Mermaid-блоки проходят проверку синтаксиса (валидатор).
3. Таблицы корректны (одинаковое число `|` в строках).
4. Нет выдуманных чисел: каждая цифра прослеживается до происхождения в данных (конспект/видео — внутренняя разметка; в читательский текст и источники video_id не попадает).
5. Есть «Что запомнить» после каждого уровня и «Чего данные не говорят» в конце.
