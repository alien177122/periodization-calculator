# Конкретный план для «Журнал Сплит» (адаптация общего плана под текущий проект)

Без кода и без HTML. Дизайн-система (Quiet UI, токены `--color-*`, сетка 4px) не меняется. Все правки — в рамках существующих стандартов `docs/design-standards/`.

---

## 1. Текущее состояние (что есть)

- **Навигация (после M0):** 3 вкладки — **Тренировка** (Программа/Разбор/Конструктор), **Теория**, **Журнал**.
- **Экраны:**
  - `CalculatorTab` — расчёт 1RM, прогрессия 8 недель, сохранённые, история, объём, карта мышц.
  - `SplitTab` / `SplitConstructorTab` — профили, сплиты, расчёты, превью, конструктор.
  - `TrainingTab` / `ActiveDayView` — текущая/следующая тренировка, завершение.
  - `JournalTab` — запись сессии, история, тренд 1RM, график.
  - `TheoryTab` — главы, статьи, маршрут.
- **Складки (`<details>`):** 5 штук, 2 из них dead code (`JournalMetricsHelp`, `JournalRpeHelp`), 3 паттерна состояния.
- **Бизнес-логика:** `packages/shared/` (расчёт прогрессии, сплиты, профили).
- **Хранилище:** `server/` (Express + SQLite), `userData` на клиенте.

---

## 2. Целевая структура экранов (Вариант A, рекомендуемый)

| Экран | Вопрос пользователя | Что переезжает / создаётся |
|---|---|---|
| **Сегодня** (новый, главный) | «Что мне делать прямо сейчас?» | Текущая неделя/день из активного расчёта, кнопка «Начать» → таймер, что изменилось с прошлого раза (RPE-дрейф, e1RM) |
| **Программа** | «По какой схеме я живу 8 недель?» | Слияние «Тренировки» и «Конструктора»: переключатель «Готовая 2×8 / Моя». Конструктор — режим, не отдельная вкладка |
| **Упражнения** | «Что это за движение и что оно мне даст?» | Досье per упражнению: нагрузка по мышцам, факты с грейдом, «что вырастет», техника, безопасность, замены |
| **Расчёт** | «Какой вес взять?» | Утилита: 1RM, проценты, веса на сегодня, RPE↔% (вынос из калькулятора) |
| **Журнал** | «Я прогрессирую?» | История + графики + подключить обе справки (Fold 4/5) |
| **Теория** | «Почему так?» | Как есть |

**Таймер** — не вкладка, а полноэкранный режим поверх всего: запускается из «Сегодня», из программы, из журнала.

**Вариант B (дешевле):** оставить 3 вкладки, но перескоупить: Калькулятор → «Разбор + расчёт», Тренировка → «Готовое», Конструктор → «Моё», плюс сквозная кнопка «В зал» (таймер) в шапку. Меньше работы, но перекрытие смыслов остаётся.

## 3. Поэтапный план (конкретно для нашего проекта)

Правило: **одна фаза = один коммит = работающее приложение**.

### Фаза 0. Карта (1–2 ч)
- **Задача:** прочитать `src/`, `packages/shared/`, составить карту: где считается прогрессия, где хранится программа, какие типы.
- **Конкретные файлы:** `src/utils/calc.ts`, `packages/shared/src/utils/split-constructor.ts`, `packages/shared/src/utils/training.ts`, `src/hooks/useCalculatorState.ts`, `src/hooks/useSplitConstructor.ts` (shared).
- **Приёмка:** документ со списком файлов и точек изменения; список «⚠ не подтверждено».

### Фаза 1. Складки (2–3 ч)
- **Задача:** единый паттерн: DOM — источник истины, React — зеркало. Убрать `preventDefault`, ручной `aria-expanded`, класс `is-open`. Сброс через `key`. Анимация через `::details-content`. Подключить или удалить обе справки (Fold 4/5).
- **Конкретные файлы:** `src/components/StrengthFormulaSection.tsx` (Fold 1), `src/components/theory/LectureSection.tsx` (Fold 2), `src/components/calculator/ProgressionPreviewChart.tsx` (Fold 3), `src/components/journal/JournalMetricsHelp.tsx`, `src/components/journal/JournalRpeHelp.tsx`, `src/hooks/useDetailsState.ts`, `src/styles/components/theory-apple.css`, `src/styles/components/training/progression-controls.css`.
- **Приёмка:** Ctrl+F находит текст в закрытой складке и он видим; Enter/Space работают; VoiceOver объявляет состояние; в `src/` нет мёртвых компонентов.

### Фаза 2. Модель «Блок» (1 день)
- **Задача:** ввести сущность «Блок» (одиночный / парный / кластерный), версия схемы → 2, миграция старых программ.
- **Конкретные файлы:** `packages/shared/src/types/index.ts`, `packages/shared/src/utils/split-constructor.ts`, `packages/shared/src/hooks/useSplitConstructor.ts`, `server/schema.js`.
- **Приёмка:** миграция идемпотентна, повторный запуск ничего не ломает, откат возможен, данные не теряются.

### Фаза 3. Движок пар (1 день)
- **Задача:** чистые функции: пересечение мышечных векторов, вердикт, хронометраж, подбор пары. Юнит-тесты.
- **Конкретные файлы:** `packages/shared/src/utils/split-pairs.ts` (уже есть), `packages/shared/src/data/split-schemes.ts`, `tests/split-constructor.test.ts`.
- **Приёмка:** становая+брусья → ok; жим+брусья → конфликт; становая+тяга → конфликт по пояснице; становая+подтягивания → предупреждение по хвату.

### Фаза 4. Таймер (2 дня)
- **Задача:** очередь фаз из Блока. Часы от `Date.now()`, тики из Web Worker. Звук, один mute, Wake Lock, общий таймер сессии.
- **Конкретные файлы:** новый `src/components/training/BlockTimer.tsx` (или в `src/utils/`), `src/components/training/ActiveDayView.tsx`, `src/hooks/` (новый хук таймера).
- **Приёмка:** свернуть вкладку на 2 мин → время ушло правильно; 10 циклов пауза/старт не плодят циклы; блок проходится до финала.

### Фаза 5. Досье упражнения (2 дня)
- **Задача:** библиотека упражнений + карточка разбора. Данные отдельно от UI, факты с грейдом.
- **Конкретные файлы:** `src/data/exercises.ts`, `src/components/split/MuscleDayGrid.tsx`, новый `src/components/exercise/ExerciseDossier.tsx`.
- **Приёмка:** смена упражнения мгновенно перерисовывает всё; ни одного факта без грейда; изометрия отличается от динамики.

### Фаза 6. Готовая программа (1 день)
- **Задача:** фулбади 2 дня × 8 недель, уже в парах. Кнопка «Взять себе» → редактируемая копия.
- **Конкретные файлы:** `packages/shared/src/data/split-presets.ts`, `src/components/split/SplitCreateDialog.tsx`.
- **Приёмка:** смена недели/паузы пересчитывает веса и длительность; длительность совпадает с таймером.

### Фаза 7. IA + discovery (2 дня)
- **Задача:** экран «Сегодня», слияние Тренировки и Конструктора, два входа на первом экране, подсказка «добавить парное» в конструкторе.
- **Конкретные файлы:** `src/components/app/AppShell.tsx`, `src/components/app/TabNav.tsx`, `src/components/app/TabPanel.tsx`, `src/screens/SplitTab.tsx`, `src/screens/SplitConstructorTab.tsx`.
- **Приёмка:** сквозной сценарий: открыл → взял готовую → изменил пару → запустил таймер → прошёл → сохранил → перезагрузил.

### Фаза 8. Журнал (2 дня)
- **Задача:** подключить справки (Fold 4/5), тренд e1RM, плато-детектор, триггер разгрузки.
- **Конкретные файлы:** `src/screens/JournalTab.tsx`, `src/components/journal/JournalProgressChart.tsx`, `src/components/journal/JournalMetricsHelp.tsx`, `src/components/journal/JournalRpeHelp.tsx`.
- **Приёмка:** окно «4 недели» считается корректно на границах; детектор не срабатывает на шуме.

### Фаза 9. Полировка (1–2 дня)
- **Задача:** печать, PWA, a11y-регресс, тесты.
- **Конкретные файлы:** `index.html`, `src/styles/`, `tests/`.
- **Приёмка:** 360px без обрезаний; reduced-motion; axe без критичных.

## 6. Инварианты (передавать агенту с любой фазой)

1. DOM — источник истины для сворачивания; `Date.now()` — источник истины для времени.
2. Один расчётный движок на все вкладки.
3. Миграции версионированы и идемпотентны.
4. Не управлять `open` из state и не вызывать `preventDefault` на summary.
5. Не добавлять ручной `aria-expanded` на нативный summary.
6. Не тащить Radix/shadcn Accordion.
7. Не сбрасывать состояние через `useEffect` — только `key`.
8. Не анимировать details через grid-transition.
9. Не оставлять справки мёртвыми: подключить или удалить.
10. Не смешивать paired sets и cluster sets в одном поле.
11. Не считать время тиками `setInterval`/`rAF`.
12. Не заводить второй источник состояния для таймера.
13. Не выдумывать ссылки, DOI и проценты. Нет источника — грейд «механизм/практика».
14. Не обещать гипертрофию в сантиметрах и «полное восстановление ЦНС».
15. Не прятать пульт пар в модалку.
16. Не ломать работающий конструктор ради редизайна.
17. Не добавлять зависимости без обоснования.
18. Не отдавать фазу без работающего приложения и отчёта: что проверено руками, что не проверено, какой долг остался.
